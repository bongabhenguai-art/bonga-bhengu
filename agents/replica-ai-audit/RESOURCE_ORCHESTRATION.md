# Resource utilization policy — Replica Entrepreneur AI

Apply to the EXISTING Bonga Bhengu OS and its revenue engine.

Use every *relevant, available and authorized* resource in the existing stack: approved GitHub repositories, installed MCP connectors, AI employee registry, central model router, open-source packages, business intelligence, CRM, design and media studio, analytics, QA and deployment tools. Discover capabilities and verify access at runtime; never claim that a resource is connected or operational without testing.

## Resource routing
- Research: approved public business sources, competitor/review intelligence, lead qualification and evidence tracking.
- Sales: Hunting, Fishing, Closer, Spy, Business Scraper, CRM, negotiation, hooks, follow-up loops and conversion reporting.
- Creative: Branding, Influencer/Avatar, Amplifier, Studio and approved publishing channels.
- Engineering: repository search, existing source and tests, CI, CodeRabbit when actually available, dependency/security scanners, Replica audit and staging validation.
- Commerce: product catalog, pricing, subscription, checkout, order ledger, authorized payment provider, payout/reconciliation and support.
- Infrastructure: reuse existing hosting, databases, object storage, queues and model endpoints where configured.

## Execution priorities
1. Reuse existing modules before adding dependencies.
2. Prefer free/open-source implementations where viable, accounting for license, maintenance, security and hardware constraints.
3. Match each job to the best permitted agent/tool and record actual execution, costs, limits, errors and outputs.
4. Preserve tenant boundaries, user consent, least privilege and approval for spending, outreach, financial movements and deployment.
5. Avoid uncontrolled fan-out, excessive API calls and duplicate tasks; use budget caps, rate limits, circuit breakers and fallbacks.
6. Keep both platform revenue and customer revenue measurable, without invented sales.

## Readiness evidence
Resource inventory (name, capability, connection status, owner, cost, permission), workflow tests, Replica audit report, CodeRabbit review result, checkout/payment provider verification, rollback plan and explicit release approval.

This is a committed implementation requirement, not proof that every resource is installed or running.
