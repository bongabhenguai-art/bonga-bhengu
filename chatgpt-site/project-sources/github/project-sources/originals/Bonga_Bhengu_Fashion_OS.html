Make.com master workflow specification

  1. Schedule: select active tenants and due jobs from the database. The agency is the first tenant, not a separate workflow.
  2. Iterate: one Iterator processes tenant/job pairs. Obtain a database job lease atomically so overlapping runs cannot process the same job.
  3. Scope: load the tenant’s approved brand guide, licensed media, feature entitlement, destinations and consent policy. Derive tenant identity server-side.
  4. Generate: reuse shared research, script, image, video and banner nodes. Adapter choices may include OpenAI, Leonardo.ai and Runway, or compatible self-hosted alternatives. Fetch secrets via a server-side credential broker; do not put provider keys in a public webhook or embed.
  5. Wait: save asynchronous provider job IDs and poll from a later scheduled run. Record failure states, bounded retries and per-tenant usage limits.
  6. Review: persist drafts for brand approval. Publishing proceeds only with recorded approval or an explicit tenant autopublish policy.
  7. Publish: resolve that tenant’s authorised website and social destinations. Use a delivery key unique to tenant, asset version and destination. Check provider delivery state before retrying uncertain posts.
  8. Measure: store provider response IDs, published URLs, timestamps and permitted metrics. Feed verified outcomes into the next brief.

A client row alone does not provide isolation. Membership checks, tenant-scoped queries, database policies, private media permissions and background-job scoping enforce it. Validate subscription events server-side before provisioning or enabling capabilities. The workflow never trusts an unauthenticated browser-supplied tenant ID.

Google Sites and production connection

In Google Sites, choose Insert → Embed → Embed code, paste this entire file, choose Next and Insert, then resize the embed and publish. The HTML works as an independent page too. Google Sites controls the outer iframe height; a mobile-friendly inner layout cannot resize that parent automatically.

Frontend functions provided here: tier navigation, keyboard controls, local image preview, editable specs, brief generation, clipboard fallback, download and WhatsApp handoff. Nothing is submitted automatically; image previews are not uploaded or attached to WhatsApp. Briefs and images reset when the page reloads.

Connect a secured backend for authentication, subscriptions, database persistence, generation, camera production, social OAuth and publishing. Website delivery should update an authorised hosted profile or supported CMS endpoint. A Google Sites embed does not itself grant write access to the Google Sites page.
