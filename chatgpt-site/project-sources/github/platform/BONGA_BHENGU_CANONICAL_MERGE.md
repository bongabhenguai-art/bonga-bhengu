# Bonga Bhengu App — Canonical Merge

**Single product name:** Bonga Bhengu App. Smart Tech OS is a legacy working label for internal technology, NOT another product or deployment.

## Source of truth
- Existing Bonga Bhengu Fashion OS: `project-sources/originals/Bonga_Bhengu_Fashion_OS.html` (retain all fashion content, working brief generation, image preview and accessibility).
- Smart technology interface: `design-system/smart-tech-os.css` and `design-system/legendary-luxury.css` (styling components, not independent applications).
- Device support: `mobile/smartphone-runtime.js` and `mobile/android-capabilities.js` (one responsive runtime).
- Execution: `platform/future-os.js`, `platform/business-workflow.js`, `platform/live-module-connectors.js` (one registry, workflow and adapter layer).
- Services: `website-builder/`, `creative-studio/`, `subscriptions/` (existing engines, never cloned).
- Navigation: Home, My Business, Tools, Activity, Connections, Account. Four tools: Website Builder, Digital Visibility, Creative Studio, Digital Banner.

## Integration sequence
1. Keep original Fashion OS file as historical source; integrate its functioning features into the canonical app shell.
2. Use exactly one entry point and one responsive navigation; remove the separate Smart Tech OS launch/home screen.
3. Register each existing capability once; remove duplicate menu items, not the underlying features.
4. Authenticate on the backend and isolate every tenant; store provider credentials server-side. Never confuse GitHub source access with OAuth authorization.
5. Show genuine job states and results; obtain user approval for external actions.
6. Test both mobile and laptop; verify the main screen loads even if optional backend services are unavailable.
7. Publish the merged app through its actual authorized deployment target. A GitHub commit alone is not deployment.
