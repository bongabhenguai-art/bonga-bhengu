## Additive physical-business intelligence contract

### Process record
Input: `businessId`, process name, description, location, owner/team participants, frequency, average duration, manual steps, existing tools, costs and evidence/source.

Output: a persisted, tenant-scoped process record and assessment with:
- `owner_dependency`: owner-only / owner-currently-does / delegable / unknown;
- `allocation`: HUMAN / TEAM / SOFTWARE / AI / SYSTEM, with rationale;
- `effort_estimate`, `impact_estimate`, `confidence` and explicit assumptions;
- `recommended_action`, responsible party, approval requirements, success metric and measured outcome.

### Time economics
- **Owner hour value:** use owner-supplied goals and productive hours; disclose assumptions and currency.
- **Business cost per hour:** use verified or owner-supplied operating costs and operating hours; if missing, mark insufficient data.
- **Opportunity cost:** estimated recoverable hours × supported hourly value; label as estimate, never actual savings.
- Never assert savings, revenue or ROI without observed before/after data.

### Systemization workflow
Map work → identify dependency → measure time/cost → recommend human/team/software/AI/system allocation → obtain approval → assign task or create SOP → verify adoption → measure time saved → learn.
