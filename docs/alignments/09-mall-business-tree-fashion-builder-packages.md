## Governing decision
**Preserve the existing Bonga Bhengu App as umbrella platform and its four products.** This source is a historical Zuxuru/Fukulisane vertical and package blueprint; its alternate prices, brand names and architecture do **not** override current Bonga configuration.

## Reusable shared engine
Business name → public DeepSearch/FBL → identity resolution → provenance-bearing evidence → coverage-aware score → business graph/profile → CIA verified account connection → growth diagnosis → opportunity → hook/offer → lead qualification → Closer → approved Studio/Builder work → provider receipt → measurement → comparable rescore → next opportunity.

Separate public, connected, owner-entered, derived and estimated information. Missing/unknown/unavailable does not equal zero.

## Four vertical contracts
| Vertical | Input | Additive home | Output and authorization |
|---|---|---|---|
| Mall / shopping centre | Centre identity, public tenant directory/map, tenant evidence | `business-system/` tenant discovery, location and relationship model | Centre inventory, independently resolved tenant profiles, aggregate opportunity report; each tenant account connection/action needs proper authority |
| Business Tree | Evidence of parent/head-office and multiple branches | `business-system/` optional multi-location relationships | Distinct branch profiles, location scores, group reporting subject to permissions; never create a tree for one location |
| Fashion | Designer profile, collection, products, brand evidence | Existing `creative-studio/`, `website-builder/`, fashion vertical from file 8 | Lookbooks, custom/wholesale leads, versioned approved assets and measurable campaigns |
| Website Builder | Verified website/domain and business profile | Existing `website-builder/` | Evidence-based website blueprint, preview, QA, approval, verified deployment, analytics and rollback |

Mall tenant identities must not be merged on name alone. Public directory information is not authorization to manage tenant accounts. Group/branch aggregation must not leak tenant data.
